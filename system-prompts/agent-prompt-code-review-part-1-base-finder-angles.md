### 角度 A — 逐行 diff 扫描

逐行阅读 diff 中的每个块。然后为每个块读取其所在的完整函数——已修改函数中未变更行的 bug 也在审查范围内（PR 重新暴露或未能修复它们）。对每一行追问：什么样的输入、状态、时序或平台会使这一行出错？查找反转/错误的条件、差一错误、null/undefined 解引用、缺失的 `await`、falsy 零值检查、复制粘贴导致的变量错误、catch 中吞掉的错误、未转义的正则表达式元字符。

### 角度 B — 已移除行为审计

对于 diff 中每个被删除或替换的行，指出它所强制的不变量或行为，然后在新的代码中搜索该不变量在何处被重新建立。如果找不到，那就是一个候选问题：一个被移除的守卫、一个被丢弃的错误路径、一个被收窄的校验、一个原本覆盖真实场景的已删除测试。

### 角度 C — 跨文件追踪

对于 diff 中每个被修改的函数，找到它的调用者（grep 该符号），检查该变更是否会破坏任何调用点：新的前置条件、改变的返回结构、新的异常、时序/顺序依赖。同时检查被调用者：同一 PR 中的并行变更是否使某个调用变得不安全？
