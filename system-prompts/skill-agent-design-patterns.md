# Agent 设计模式

本文档涵盖在 Claude API 上构建代理的决策启发式方法：使用哪些原语、如何设计工具面，以及如何在长运行过程中管理上下文和成本。关于各工具的机制和代码示例，请参见 `tool-use-concepts.md` 和各语言特定文件夹。

---

## 模型参数

| 参数 | 何时使用 | 预期效果 |
| --- | --- | --- |
| **自适应思考**（`thinking: {type: "adaptive"}`） | 当你希望 Claude 自主控制何时思考以及思考多少时 | Claude 根据请求决定思考深度，并在工具调用之间自动交错思考。无需调整 token 预算。 |
| **Effort**（`output_config: {effort: ...}`） | 调整详尽程度与 token 效率之间的权衡时 | 较低的 effort → 更少且更紧凑的工具调用、更少的前置说明、更简洁的确认信息。`medium` 通常是较好的平衡点。当正确性比成本更重要时使用 `max`。 |

关于模型支持和参数详情，请参见 `SKILL.md` §思考与努力。

## 设计你的工具面

### Bash 与专用工具

Claude 不知道你的应用程序的安全边界、审批策略或 UX 面。Claude 发出工具调用；你的 harness 处理它们。这些工具调用的形状决定了 harness 能做什么。

**Bash 工具** 给予 Claude 广泛的编程杠杆 —— 它几乎可以执行任何操作。但它只给 harness 一个不透明的命令字符串，每个操作的形状相同。将一个操作提升为 **专用工具** 则给 harness 提供了一个带类型参数的操作特定钩子，可以拦截、门控、渲染或审计。

**何时将操作提升为专用工具：**

- **安全边界。** 需要门控的操作是自然候选。可逆性是一个有用的标准：难以逆转的操作（外部 API 调用、发送消息、删除数据）可以放在用户确认后面。`send_email` 工具容易门控；`bash -c "curl -X POST ..."` 则不然。
- **陈旧性检查。** 专用的 `edit` 工具可以在文件自 Claude 上次读取后发生更改时拒绝写入。Bash 无法强制执行该不变性。
- **渲染。** 某些操作受益于自定义 UI。Claude Code 将提问提升为一个工具，以便它可以作为模态框渲染、呈现选项并在代理循环中阻塞直到得到回答。
- **调度。** 只读工具如 `glob` 和 `grep` 可以标记为并行安全。当相同的操作通过 bash 运行时，harness 无法区分并行安全的 `grep` 和并行不安全的 `git push`，因此必须序列化。

**经验法则：** 从 bash 开始以获得广度。当需要门控、渲染、审计或并行化时，再提升为专用工具。

## Anthropic 提供的工具

| 工具 | 端 | 何时使用 | 预期效果 |
| --- | --- | --- | --- |
| **Bash** | 客户端 | Claude 需要执行 shell 命令 | Claude 发出命令；你的 harness 执行它们。提供参考实现。 |
| **文本编辑器** | 客户端 | Claude 需要读取或编辑文件 | Claude 通过你的实现查看、创建和编辑文件。提供参考实现。 |
| **计算机使用** | 客户端或服务端 | Claude 需要与 GUI、Web 应用或可视化界面交互 | Claude 截取屏幕截图并发出鼠标/键盘命令。可以自托管（你运行环境）或由 Anthropic 托管。 |
| **代码执行** | 服务端 | Claude 需要在你不想管理的沙盒中运行代码 | Anthropic 托管的容器，内置文件和 bash 子工具。无客户端执行。 |
| **网页搜索/获取** | 服务端 | Claude 需要训练截止日期之后的信息（新闻、当前事件、最新文档）或特定 URL 的内容 | Claude 发出查询或 URL；Anthropic 执行并返回带引用的结果。 |
| **记忆** | 客户端 | Claude 需要在会话之间保存上下文 | Claude 读/写 `/memories` 目录。你实现存储后端。 |

**客户端** 工具由 Anthropic 定义（名称、模式、Claude 的使用模式），但由你的 harness 执行。Anthropic 提供参考实现。**服务端** 工具完全在 Anthropic 基础设施上运行 —— 在 `tools` 中声明它们，Claude 处理其余部分。

## 组合工具调用：程序化工具调用

在标准工具使用中，每次工具调用都是一次往返：Claude 调用工具，结果进入 Claude 的上下文，Claude 进行推理，然后调用下一个工具。三个顺序操作（读取资料 → 查询订单 → 检查库存）意味着三次往返。每次往返增加延迟和 token，而大部分中间数据再也不需要了。

**程序化工具调用（PTC）** 让 Claude 将这些调用组合成一个脚本。脚本在代码执行容器中运行。当脚本调用工具时，容器暂停，调用执行（客户端或服务端），结果返回给正在运行的代码 —— 而不是 Claude 的上下文。脚本使用正常的控制流（循环、过滤、分支）处理结果。只有脚本的最终输出返回给 Claude。

| 何时使用 | 预期效果 |
| --- | --- |
| 许多顺序工具调用，或希望在大型中间结果到达上下文窗口之前进行过滤时 | Claude 编写将工具作为函数调用的代码。在代码执行容器中运行。Token 成本随最终输出而非中间结果增长。 |

## 扩展工具和指令集

| 功能 | 何时使用 | 预期效果 |
| --- | --- | --- |
| **工具搜索** | 有很多工具可用，但每个请求只与少数相关。不想将所有模式都加载到上下文中。 | Claude 搜索工具集并仅加载相关模式。工具定义被追加而非替换 —— 保留缓存（见下文缓存部分）。 |
| **技能** | 任务特定的指令，Claude 只应在相关时加载。 | 每个技能是一个包含 `SKILL.md` 的文件夹。技能的描述默认存在于上下文中；Claude 在任务需要时读取完整文件。 |

这两种模式都保持固定上下文较小，并按需加载详细信息。

## 长期运行代理：管理上下文

| 模式 | 何时使用 | 预期效果 |
| --- | --- | --- |
| **上下文编辑** | 上下文在多轮后变得陈旧（旧的工具结果、已完成的思考）。 | 基于可配置阈值清除工具结果和思考块。保持记录简洁而不进行总结。 |
| **压缩** | 对话可能达到或超过上下文窗口限制。 | 早期上下文在服务端被总结为一个压缩块。参见 `SKILL.md` §压缩 以了解关键的 `response.content` 处理。 |
| **记忆** | 状态必须在会话之间持久化（而不仅仅是在一个对话内）。 | Claude 在记忆目录中读/写文件。在进程重启后依然存在。 |

**如何选择：** 上下文编辑和压缩在会话内运作 —— 编辑修剪陈旧的轮次，压缩在接近限制时进行总结。记忆用于跨会话持久化。许多长期运行的代理同时使用这三种。

## 代理的缓存策略

**首先阅读 `prompt-caching.md`。** 它涵盖前缀匹配不变性、断点放置、静默无效因素审核，以及为什么在会话中间更改工具或模型会破坏缓存。本节仅涵盖这些约束的代理特定解决方案。

| 约束（来自 `prompt-caching.md`） | 代理特定解决方案 |
| --- | --- |
| 在会话中间编辑系统提示词会使缓存失效。 | 在 `messages` 数组中追加 `<system-reminder>` 块代替。缓存前缀保持不变。Claude Code 使用此方法进行时间更新和模式切换。 |
| 在会话中间切换模型会使缓存失效。 | 使用更便宜模型的 **子代理** 处理子任务；主循环保持在一个模型上。Claude Code 的 Explore 子代理使用 Haiku 就是这种方式。 |
| 在会话中间添加/移除工具会使缓存失效。 | 使用 **工具搜索** 进行动态发现 —— 它追加工具模式而非替换，因此现有前缀得以保留。 |

对于多轮断点放置，使用顶级自动缓存 —— 参见 `prompt-caching.md` §放置模式。
