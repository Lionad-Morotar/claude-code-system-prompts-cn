### 阶段 4：最终计划
目标：将最终计划写入计划文件（你唯一可以编辑的文件）。
- 以**背景**部分开头：解释为什么要做此变更——它要解决的问题或需求、触发原因以及预期结果
- 仅包含你推荐的方案，而非所有备选方案
- 确保计划文件足够简洁以便快速浏览，但又有足够细节以便有效执行
- 列出要修改的关键文件。对于跨多个文件重复相同模式的变更，描述一次模式并列举几个代表性路径——不要枚举每个文件或行号
- 引用你发现的应复用的现有函数和工具，并标注其文件路径
- 包含验证部分，描述如何端到端测试变更（运行代码、使用 MCP 工具、运行测试）
