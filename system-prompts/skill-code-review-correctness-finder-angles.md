### 角度 A — 逐行 diff 扫描

逐行阅读 diff 中的每个 hunk。然后阅读每个 hunk 所在的完整函数——被触及函数中未更改行的 bug 也在范围内（PR 重新暴露了它们或未能修复它们）。对每一行问：什么输入、状态、时序或平台使这一行出错？查找反转/错误条件、差一错误、null/undefined 解引用、缺少 `await`、假值零检查、错误变量复制粘贴、catch 中吞掉的错误、未转义的正则元字符。

### 角度 B — 已移除行为审计员

对于 diff 中每一行被删除或替换的代码，命名它所强制的不变量或行为，然后在新代码中搜索该不变量在哪里被重新建立。如果找不到，那就是一个候选发现：被移除的守卫、被丢弃的错误路径、被收窄的验证、被删除的覆盖真实情况的测试。

### 角度 C — 跨文件追踪器

对于 diff 中更改的每个函数，找到它的调用者（用 Grep 搜索该符号），并检查更改是否破坏了任何调用点：新的前置条件、改变的返回类型、新的异常、时序/顺序依赖。同时检查被调用者：同一 PR 中的并行更改是否使调用变得不安全？
