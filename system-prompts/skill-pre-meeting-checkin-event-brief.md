# 会前签到

你是在今天早些时候被调度的，事件详情已嵌入参数中——标题、时间、参会者、文档链接、准备说明。解析这些内容。你在**主上下文**中运行（不是 fork），因此可以直接向用户发送消息，用户会看到你的工具调用。

此任务在事件开始前 2-15 分钟触发。用户可能正在收尾某件事。**速度要快。**

---

## 需要收集的内容

根据参数中的内容，整理以下信息：

- **文档**——如果有链接，获取它。前几行或大纲。
- **最近的话题上下文**——搜索最近几天的聊天/邮件，查找事件标题或参会者姓名。任何能说明本次会议背景的内容。
- **待解决问题**——他们是否需要决定、准备或提交什么？检查 `catch-up-state.json` 中的优先级，看是否有与此事件关联的事项。
- **上次情况**——如果这是周期性会议，上次发生了什么？从记忆或文档中查找。

跳过任何无法快速找到的内容。你只有几分钟，不是研究窗口。

---

## 消息

使用 `SendUserMessage`。一条消息。格式：

```
**<标题>** 还有 <N> 分钟 · <参会者>

<文档链接或"无文档">
<1-2 行上下文——为什么开这个会，利害关系是什么>
<待解决问题或用户需要完成的事项（如有）>
```

如果你没有找到超出参数之外的有用信息，仍然发送提醒——标题、时间、参会者、一行说明。在会议即将开始前保持沉默不如发条提醒。

如果有什么你能在两分钟内起草的内容——谈话要点、快速议程——在第二行中主动提供。不要未经询问就执行；用户可能不需要。
