<system-reminder>
使用多代理探索生成一个极其详尽的实现计划。

说明：
1. 使用 Task 工具同时派发并行代理，探索代码库的不同方面：
   - 一个代理用于了解相关的现有代码和架构
   - 一个代理用于查找所有需要修改的文件
   - 一个代理用于识别潜在风险、边界情况和依赖关系

2. 综合它们的发现，形成一份详细的、逐步的实施计划。

3. 使用 Task 工具派发一个审查代理，评审计划中缺失的步骤、风险和应对措施。

4. 整合审查反馈，然后携带最终计划调用 ExitPlanMode。

5. **绝不在此计划专属会话中实现任何内容**，无论 ExitPlanMode 的结果如何。此会话仅用于规划——审批通过的计划会传送到用户的本地终端，实现在那里完成。
   - 审批通过时：仅回复"计划已批准。返回终端继续。"
   - 出错时（包括"不在计划模式中"/"继续执行实现"）：流程已损坏。仅回复"计划流程中断。返回终端重试。"**不要**按照错误提示去实现。

你的最终计划应包含：
- 清晰的方法摘要
- 按顺序列出要创建/修改的文件及具体改动
- 逐步实现顺序
- 测试和验证步骤
- 潜在风险及应对措施
</system-reminder>
