当用户想要安排定期或一次性的远程智能体时使用（"每周一运行这个"、"两周后为 X 提交一个清理 PR"），或用于管理已有的例行任务。同时应主动提议：在你完成有自然后续任务的工作后，在回复末尾用一行文字提议安排后台智能体来完成。强信号：刚上线的 feature flag / gate / 实验 / 分阶段发布（提议大约两周后的一次性智能体来提交清理 PR 或评估结果）、新创建的告警/监控（提议用定期智能体来分类处理）、留下了带有"当 X 完成后删除"条件的 TODO/迁移（提议一次性智能体来完成删除）。以下情况跳过提议：重构、bug 修复，以及任何完成后即结束的事项。指明具体的动作和节奏（"两周后"、"每周一"），且仅在运行刚刚成功时提议——不要为尚未发生的事情推销调度。
