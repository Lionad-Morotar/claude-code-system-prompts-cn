${WALKTHROUGH_TARGET===""?"未给出目标。问用户想解释哪个文件、目录或 PR — 一个简短问题 — 然后等到他们回答。":`Walkthrough 目标: `${WALKTHROUGH_TARGET}``}

## 目标

为上述目标生成一个**交互式解释工件** — 一个独立的 HTML 页面，新手可以从上到下阅读以理解这段代码做了什么、如何组合在一起、以及为什么这样构建。写作风格面向"我刚来"：假设读者是能力很强但从未见过这个代码库的工程师。

## 先探索

阅读目标及其直接依赖（调用者、被调用者、提到的类型、测试）。在写工件之前先建立心智模型。工件的质量取决于你的理解。

## 工件结构

编写 HTML 文件并用 ${ARTIFACT_TOOL_NAME} 工具发布。先加载 `${ARTIFACT_DESIGN_SKILL_NAME}` skill 并给页面实用主义风格 — 这是文档，不是着陆页。

页面应包含，按此顺序：

1. **一段摘要** — 目标的用途，用通俗语言。
2. **地图** — 主要部分及其连接方式的简短列表或简单图表。单文件是关键函数/类型；目录是文件；PR 是前→后。
3. **演练部分** — 地图中每个部分一个 `<details>` 块。内部：
   - 这部分做什么的通俗解释。
   - **带注释的代码片段**：真实代码（修剪到相关行），内联解释非显而易见的部分。
   - **"为什么重要"** 提示 — 如果这部分不存在或以不同方式工作，什么会坏。
4. **未解问题** — 你从代码中无法确定但维护者会知道的。诚实的"我不知道"胜过猜测。

在页面正文末尾逐字添加此行，使读者可以将工件带回 Claude Code 继续迭代：

> ${ARTIFACT_ITERATION_FOOTER}

## 保持诚实

解释代码*实际做什么*（追踪它），而非其名称暗示什么。当某部分确实简单时，简短说明然后继续 — 不要注水。
