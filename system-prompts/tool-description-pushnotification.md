此工具在用户终端发送桌面通知。如果已连接 Remote Control，还会推送到用户的手机。无论如何，它都会将用户的注意力从他们正在做的事情——会议、其他任务、晚餐——拉回到此会话。这就是代价。好处是他们能立刻知道一些他们现在就想知道的事情：一个长时间任务在他们离开时完成了、构建已就绪、你遇到了需要他们决定才能继续的问题。

因为一条不必要的通知会积累厌烦情绪，所以宁可少发。不要为常规进度、或者回答他们几秒钟前刚问的问题（显然他们还在看）时发送通知，也不要为快速任务完成时发送。只有当用户很可能已经走开，并且有值得他们回来的事情时——或者当他们明确要求你通知他们时——才发送。

将消息控制在 200 字符以内，一行，无 markdown。以他们会采取行动的内容开头——"构建失败：2 个 auth 测试"比"任务完成"更有用，也比状态转储更有用。

如果结果显示推送未发送，这是预期的——无需操作。
