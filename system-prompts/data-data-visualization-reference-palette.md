# 参考调色板

这是数据可视化方法的**参考实例**：方法所需的每个参数，都用经过验证的默认调色板填充。技能的其余部分是系统无关的——**要针对你的品牌，替换此文件中的值**并重新运行验证器。其他内容不变。

## 如何使用这些值

以下所有内容都是纯 hex。在 HTML 图表中，**在文件顶部的本地 `<style>` 块中将你使用的槽位定义为 CSS 自定义属性**，然后在整个文件中按角色引用它们——这样亮/暗值在一个地方切换，图表主体是针对角色而非原始 hex 编写的：

```css
.viz-root {
  color-scheme: light;
  --surface-1:      #fcfcfb;   /* chart surface */
  --text-primary:   #0b0b0b;
  --text-secondary: #52514e;
  --series-1:       #2a78d6;   /* categorical slot 1 */
  /* …only the roles this chart uses */
}
@media (prefers-color-scheme: dark) {
  :root:where(:not([data-theme="light"])) .viz-root {
    color-scheme: dark;
    --surface-1:      #1a1a19;
    --text-primary:   #ffffff;
    --text-secondary: #c3c2b7;
    --series-1:       #3987e5;
  }
}
:root[data-theme="dark"] .viz-root {
  color-scheme: dark;
  --surface-1:      #1a1a19;
  --text-primary:   #ffffff;
  --text-secondary: #c3c2b7;
  --series-1:       #3987e5;
}
```

在两个作用域下声明暗色值，如上所示——媒体查询覆盖操作系统设置；`data-theme` 作用域覆盖查看器的主题切换，两者都必须生效（`:not(…)` 守卫让亮色标记胜过操作系统暗色；`:where()` 保持媒体块低于切换作用域）。

## 分类调色板

两种模式都已选中。暗色列是相同的八种色相为暗色表面调整后的结果，不是独立的调色板：

| 槽位 | 色相 | 亮色 | 暗色 |
|------|------|------|------|
| 1 | blue | `#2a78d6` | `#3987e5` |
| 2 | green | `#008300` | `#008300` |
| 3 | magenta | `#e87ba4` | `#d55181` |
| 4 | yellow | `#eda100` | `#c98500` |
| 5 | aqua | `#1baf7a` | `#199e70` |
| 6 | orange | `#eb6834` | `#d95926` |
| 7 | violet | `#4a3aa7` | `#9085e9` |
| 8 | red | `#e34948` | `#e66767` |

此顺序在两种模式下都通过了默认*相邻*对列表（堆叠、条形、折线）的每个硬性门槛：最差相邻 CVD ΔE 亮色 9.1 / 暗色 8.4（OKLab ×100，目标 ≥8），最差相邻正常视觉 ΔE 亮色 19.6 / 暗色 19.3（底线 ≥15）。在 `--pairs all`（散点、气泡、分级统计图、小多图）下，完整的八种无法清除底线——当所有 28 对都在起作用时没有任何排序可以（对列表不再依赖顺序），且根据已记录调色板规则重新调整步骤不可行——因此这些图表形式带有系列上限：**前四个槽位在两种模式下都验证所有对**（暗色运行落在 6–8 CVD 底线区间，因此使用辅助编码——直接标签、间隙或纹理）。超过四个，折叠为"其他"、分面或直接标注。三个亮色模式槽位（magenta、yellow、aqua）在亮色表面上的对比度低于 3:1：**relief 规则**适用（使用可见直接标签或表格视图）。暗色步骤是为暗色区间选择的（OKLCH L ≈ 0.48–0.67，在暗色表面上 ≥ 3:1）并作为一组验证。（此顺序在 2026 年 7 月替换了较早的默认值——相同的八种色相和步骤，重新排序——在较早顺序在两种模式下都未能通过正常视觉底线之后。）当你替换为自己的渐变时，将你的调色板保持在完整门槛。

槽位**排序**是 CVD 安全机制，不是装饰——它通过枚举排序并选择最大化最小相邻 ΔE 的那一个而得出（参见 `color-formula.md` § Themes）。当你替换为品牌的色相时，做同样的事情：在候选排序上运行验证器并保留最好的。

## 顺序色相

默认单色相：**蓝色**，浅→深。当两个顺序上下文同时出现时，第二个取下一个分类槽位的色相（绿色），每个作为自己的一色相渐变。

| step | hex | step | hex | step | hex | step | hex |
|---|---|---|---|---|---|---|---|
| 100 | `#cde2fb` | 250 | `#86b6ef` | 400 | `#3987e5` | 550 | `#1c5cab` |
| 150 | `#b7d3f6` | 300 | `#6da7ec` | 450 | `#2a78d6` | 600 | `#184f95` |
| 200 | `#9ec5f4` | 350 | `#5598e7` | 500 | `#256abf` | 650 | `#104281` |
| | | | | | | 700 | `#0d366b` |

完整的 100→700 范围用于**顺序**编码（连续幅度——热力图、分级统计图），其中最浅步骤表示"接近零"并允许退向表面。对于**顺序**渐变（离散有序标记——漏斗阶段、层级——使用 `--ordinal` 验证），最接近表面的步骤仍必须清除 2:1：亮色上，起始不浅于**步骤 250**（`#86b6ef`，2.06:1）；暗色上，结束不深于**步骤 600**（`#184f95`，2.15:1）。

## 发散对

**blue ↔ red** — 暖/冷两极被读为相反。中性中点是灰色（亮色 `#f0efec`，暗色 `#383835`）。每臂步数相等。（blue↔aqua 被拒绝——都是冷色，中点不被读为"无"。）

## 状态调色板（固定——永不主题化）

| 角色 | hex | 亮色表面对比度 | 暗色表面对比度 |
|------|-----|----------------|----------------|
| good | `#0ca30c` | 3.27 | 5.19 |
| warning | `#fab219` | 1.79 | 9.49 |
| serious | `#ec835a` | 2.57 | 6.60 |
| critical | `#d03b3b` | 4.68 | 3.62 |

暗色：相同的四个步骤——在暗色表面（`#1a1a19`）上都清除 3:1 并与暗色分类槽位保持区分。在亮色表面上，warning 和 serious 按设计低于 3:1；**图标 + 标签**配对是缓解措施，因此状态颜色从不单独携带含义。这些步骤故意与分类槽位区分开来，这样状态颜色不会冒充序列——区分度足够使任何内容在扫视时不会碰撞，但不足以让色相单独承载区分：通过序列底线自身的标准衡量（未模拟 ΔE ≥ 15），每种模式约九对分类-状态对低于 15——在亮色模式下 red vs critical 和 yellow vs warning 都测得 4.8，亮色成功文本绿色 `#006300` 距序列绿色 10.1；green vs status-good（9.7）在两种模式下都保持，因为两个 hex 都是模式不变的。规则是通用的：任何序列颜色旁边的同色族状态或增量提示依赖图标 + 标签配对和位置；从不单独依赖色相。

## 纹理填充（无障碍通道）

一种手绘**"线条"**填充，仅在 **45° 及其 135° 镜像**使用。色上色（填充自身渐变的较深步骤）。在值刻度上它是*有序的*（旋转步骤随幅度变化；臂角承载发散符号）。由无障碍设置、打印或 `forced-colors` 触发——从不装饰，从不默认开启。

## 表面（供验证器使用）

- 亮色图表表面：`#fcfcfb`
- 暗色图表表面：`#1a1a19`

这些是验证器的内置默认值。**当你替换为自己的调色板时，对照你自己的表面重新运行：**
`--surface <your-light> --mode light` 和 `--surface <your-dark> --mode dark` —对比度和区间结果仅对照图表实际渲染的表面才有意义。

## 过滤控件

过滤器是标准 UI，不是图表组件——图表层只添加 `interaction.md` 中的组合规则。日期范围控件是预设行列表（今天、最近 7/30/90 天、月至今），选择由 16px 粗体勾选标记，悬停作为幽灵洗色，自定义范围在页脚的极细线后面。维度过滤器是标准组合框。

## 字体与数字

所有内容——包括英雄数字——都使用系统无衬线体：`system-ui, -apple-system, "Segoe UI", sans-serif`。任何地方都不使用展示体或衬线体。大型独立数字（英雄数字、统计块值）使用默认比例数字；保留 `font-variant-numeric: tabular-nums` 用于必须垂直对齐的列（表格行、轴刻度）。在此替换为品牌的 UI 无衬线体。
