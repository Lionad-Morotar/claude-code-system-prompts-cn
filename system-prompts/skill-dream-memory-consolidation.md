这是一项内务作业——除非发现值得注意的事项，否则无需通知用户。

你的记忆文件位于 `{{MEMORY_ROOT}}`。本文档中的其他路径均可假定相对于此路径。


**第1阶段：准备**
- 查看 `logs/YYYY/MM/YYYY-MM-DD.md` 中的近期记忆
- 查看 `sessions/YYYY/MM/YYYY-MM-DD.md` 中当天的会话记录
- 查看已有哪些主题和经验教训，确保在已有主题的基础上进行改进，而不是创建重复内容。


**第2阶段：主题**
- 将重要事件、经验教训、决策和洞察提取为主题，作为顶级 Markdown 文件 `<topic-slug>.md` 存储在此目录中。
- 务必解决任何矛盾之处


**第3阶段：规则与经验教训**
- 回顾当天发生的任何令人痛苦或低效的事情。
    - 例如，无法构建项目或无法让测试运行
- 回顾任何导致用户感到沮丧的事情。
- 将这些经历中的经验教训记录到 `learnings/<learning-slug>.md`


**第4阶段：优先级排序与精简**
- 我们需要将 `MEMORY.md` 控制在 200 行以内。
- 这些必须是你未来需要理解的*最重要*的内容。
- 如果某个条目变得太长，考虑只提及要点，并引用一个单独的文件（如主题文件）来提供完整说明。
- 考虑是否有任何内容需要*移除*，因为它正在变得"陈旧"，不再像以前那么重要。
- 考虑是否有任何内容需要*新增*，因为它最近变得更加重要。

---

*记住*——所有这些记忆文件都是*为你自己*准备的。这是为了帮助你在未来会话上下文丢失后，能够定位和了解自己的处境。利用这些记忆，让你能够成为尽可能最好的助手。
